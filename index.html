JARVIS Mission Control Dashboard

Problem

Ten AI agents were running across 37 active automation workflows, but their state lived in three unconnected places: the automation platform, a Postgres database, and a Telegram chat. Answering "which agents are live, what is assigned, and what has this cost" meant opening three tools and reconciling them by hand.

What I built

A custom Obsidian plugin in TypeScript that puts the whole operation in one sidebar: agent roster with live status, task assignment straight to any agent, a 30-day revenue and spend overview, and one-click buttons that fire automation workflows. Each panel loads independently, so one failing data source degrades a single card instead of blanking the dashboard. It authenticates with a purpose-built least-privilege database role — read on three tables, write on one, deletes refused at the database — rather than the all-access key this kind of tool usually ships with.

GoHighLevel CRM Setup — Internal Tooling

Problem

Outbound lead tracking for two of my own early-stage businesses — Vera BPO (an AI answering service) and Cobalt Media Co (an SMMA) — was spread across scattered notes. Outreach ran through several contact channels at once, and there was no reliable way to see who had already been contacted, which channel they were reached on, or who had actually replied. Leads were being lost to bookkeeping rather than to disinterest.

What I built

Set up GoHighLevel as the CRM of record for both businesses, tracking leads and clients from first outreach through to reply, with a dedicated sales pipeline for Cobalt Media Co. Outreach is logged per channel, so a lead’s history — contacted where, when, and whether they responded — sits in one place instead of across notes.

Separately, and deliberately not yet pointed at that workspace, I wrote a provider-agnostic CRM sync layer with interchangeable GoHighLevel and HubSpot adapters, so a business can switch CRM without touching the calling code. Built against the GoHighLevel LeadConnector API: token auth with the required version header, contact upsert, and email/phone normalisation to E.164 before send. Credentials live in a locked-down table with default-deny access, and the code detects a missing credential and skips cleanly instead of breaking the call flow around it. It runs on placeholder credentials today and has never been connected to a live GoHighLevel account.

Measurable result

No metrics yet, and none are claimed. This is internal tooling for two businesses still in their early stages, not a completed client engagement — both are pre-revenue, so any conversion, booking or retention figure would be meaningless. What changed is operational: lead status is now a lookup rather than a reconstruction. Evidence here is a written description only; screenshots and any real numbers will follow once the businesses are properly launched.

n8n Automation Pipeline

Problem

Sourcing qualified trucking-carrier leads meant querying a federal registry by hand, stripping out carriers that did not fit, checking each one against records already contacted, and writing an individual pitch. It was several hours of repetitive work for a list that went stale within days.

What I built

A 12-stage n8n pipeline that runs unattended every morning: it queries the federal carrier registry, filters to the target profile, scores each carrier for fit with an AI model and drafts a tailored opening line, removes anyone already in the database, writes the result to Postgres, and posts a digest to Telegram. Full execution tracing is wired in, so a bad run is visible rather than silent.

Measurable result

12,845 qualified leads generated across 96 days of unattended operation — 97% with a phone number, 99% with an email. Roughly 15 new scored leads land every morning with zero manual steps, and every run in the retained execution window completed successfully.
